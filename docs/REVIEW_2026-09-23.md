# Independent repository review — 2026-09-23

This is a pre-correction review, not a certification of the running service. Target: the existing per-user MONA JupyterHub launcher. The reviewer did not implement code fixes, start services, train models, modify scientific data, or contact ELab. Historical Reviewer instructions supplied the seven review dimensions; archived conversations were context, not operational authority.

## Executive findings

- Fix frame-gap handling before trusting newly produced tracks or ABP estimates. Sparse observations currently become adjacent-time observations in the main MSD implementation.
- Fix state restoration, model provenance/weight retention, and filename containment before promoting this checkout. These affect the workflow already exposed in the web interface.
- Preserve research artifacts and historical reports during cleanup. Missing research interfaces are scope decisions, not defects that require automatic integration.

Priorities: P0 = immediate security/data-integrity blocker; P1 = release correctness/reliability; P2 = bounded maintenance or operational improvement; P3 = future design. No externally exploitable P0 was demonstrated for the configured loopback Jupyter launcher. Standalone exposure has a separate P0 condition below.

## Findings and correction acceptance criteria

### R1 — P1: startup separates app state from persisted state

**Evidence:** `web/state.py:80–114` replaces `users`, `training_jobs`, and `background_jobs`. `web/app.py:83–86` imports those dictionaries before lifespan calls the loaders. Consequently the app keeps old objects while serialization sees replacements. An isolated temporary-file reproduction loaded an old job, inserted a new job through the original reference, and saved: identity comparison was false and only the old job remained on disk. Only `running`, not `queued`, jobs are reconciled after restart. JSON writes also directly truncate their destinations without serialization around whole writes.

**Owner:** Web + Maintenance. Preserve object identity with in-place updates, write complete JSON snapshots atomically with serialized writers, and reconcile nonterminal jobs when no worker survives. Test startup with existing records, app-like imported references, a subsequent new job, restart, queued/running recovery, and concurrent save operations. Do not imply daemon-thread jobs resume computation.

### R2 — P1: tracker links across elapsed gaps larger than its configured limit

**Evidence:** `src/tracking/track_particles.py:102–146` iterates only frames that contain detections; it increments gap by one observed iteration and expires after assignment. Isolated input with detections at frames 0 and 100, within 30 px, and `max_gap=1` returned track ID 0 for both.

**Owner:** Core + Maintenance. Expire candidates before assignment using elapsed frame numbers, with `max_gap` defined as the number of missing frames. Test no missing frames, the allowed boundary, one over the boundary, all-empty intermediate frames, and another particle present during the gap. Preserve normal consecutive-frame behavior.

### R3 — P1: main MSD/AMSD silently compresses missing time

**Evidence:** `src/analysis/analyze_tracks.py:47–60,87–98` filters interpolation/NaN angles then uses row offsets as frame lags. Frames 0 and 100 with a displacement of 1 px and angle difference 1 rad yielded lag-1 MSD and AMSD of 1, each with one sample. The same functions back web ABP analysis. `src/analysis/compare_filtered_abp.py:90–143` already provides exact-frame-lag calculations, creating inconsistent scientific semantics between tools.

**Owner:** Core. Pair observations by actual frame difference; preserve lag units and counts; handle empty and insufficient data without failed reductions in `fit_msd` (`t.max()` precedes its exception handler). Test sparse/consecutive/interpolated observations and missing angles. Clarify angular unwrapping across gaps; long missing intervals cannot recover unseen rotations. Do not silently overwrite historical result tables after changing semantics. Existing reports using these functions need later provenance review and deliberate regeneration.

### R4 — P1: model IDs do not identify immutable weights/configuration

**Evidence:** `web/app.py:785–803` writes every training run of a particle to `{particle_name}_weights.pth` while appending entries with distinct job IDs. Retraining changes what earlier IDs load; deleting an earlier entry can remove weights used by another entry. `_cli_model_entry` at `web/app.py:922–941` obtains configuration from mutable `src/config.yaml`, not the saved training run. `load_model` uses that configuration to choose architecture.

**Owner:** Web/Core interface. Save new training weights under job-specific paths and preserve legacy entries safely when deleting shared paths. Discover configuration from explicit summary metadata or adjacent run `config.yaml`; label absent metadata instead of silently taking current experiment settings. Test two same-particle runs, deleting one, run architecture overriding global configuration, and metadata absence. No training run is required to test path/provenance behavior.

### R5 — P1 in Jupyter / P0 if publicly exposed standalone: path and identity boundaries are inconsistent

**Evidence:** `web/routers/files.py:218–223` accepts any filename ending in `.csv` then writes `results / file.filename`; an absolute component discards the parent and `../` escapes it. `web/routers/tdms_explorer.py:178–207` interpolates raw output names into output paths and creates parents. Similar joins exist in batch detection (`web/app.py:1530`), tracking (`1618–1625`), visualization, and ABP (`1786`). Other routes use validated names, so protection is uneven. No destructive probe was performed.

**Owner:** Web. Centralize leaf-name validation plus resolved-path containment, including existing symlinks, for application-managed reads/writes/deletes. Cover CSV uploads, output names, samples/models/masks, tracking/analysis inputs, and TDMS exports. Keep explicitly selected server input paths as a documented Jupyter feature rather than accidentally disabling it. Reject invalid names before creating files or jobs. Test absolute paths, traversal, separators, empty names, symlinks, and valid names using temporary directories.

`web/auth.py` returns username/session data without issuing a session credential; `state.require_user` checks registration, not proof of login, in standalone mode, and numerous app routes bypass that helper. The Jupyter launcher binds `127.0.0.1` and delegates access to Hub authentication; that reduces remote exposure but does not turn standalone login into authentication. Keep deployment scoped to Hub and clearly document standalone limitations. A public standalone release requires a separate authentication/authorization design, including WebSockets, plus credential hashing changes; do not graft a partial scheme into this cleanup.

### R6 — P1 deployment gate: package layout and installed checkout differ

**Evidence:** `setup.py:6–14` packages only `web` and four web dependencies; `web/app.py:33–43` imports `utils` from sibling `src`, and crescent measurement from sibling `tools`. A wheel installed without the repository cannot supply those paths. Existing source-checkout deployment can work and should be documented distinctly. `src/requirements.txt` also installs DeepTrack from a mutable development branch.

Parent-agent environment inspection found the installed `mona-track` 0.2.0 editable distribution and `web` import outside this CWD point to `/home/mona/MONA_LodeSTAR`, while this review changes `/home/edgarharutyunyan/MONA_LodeSTAR`. Local ignored `mona_track.egg-info` reports stale 0.1.0 metadata. Fixes here are not deployed merely because local tests pass.

**Owner:** Maintenance + Web. State the supported editable-source installation contract and environment dependencies, verify the launcher/import origin from outside the checkout, and record the release checkout/revision before a deliberate deployment step. Do not edit the other checkout or reinstall globally as implicit cleanup. Packaging a standalone wheel is a separate choice; an honest source-checkout contract is sufficient for the current target.

### R7 — P2: ELab wrapper rejects forwarded commands

**Evidence:** `tools/elab_cli.py:28–45` creates empty `simple`/`full` subparsers then calls `parse_args`; downstream command arguments are rejected before dispatch. Local parser invocation confirmed `unrecognized arguments` for a `simple patch-item` invocation; `simple patch-item --help` shows only the empty outer help. No network request occurred.

**Owner:** Tools. Forward the selected subcommand argument vector, preserve downstream help and exit status, and test forwarding with mocked dispatchers so no ELab write occurs. Direct inner CLI remains the available workaround.

### R8 — P2: live documentation and research invocation paths have drifted

**Evidence:** `docs/BRANCH_GUIDES.md` describes detection as lacking CLI model discovery although `_discover_cli_models` exists, gives `PYTHONPATH=src` for a diagnostic whose model now lives in `src/detection`, and advertises the SPA at roughly 1,500 lines despite its substantially larger current size. `debug/diagnostics/diagnose_skip_connections.py:13` adds its own directory rather than the moved source directory. Cross-reference the companion Markdown and web-integration audits for the full stale-link inventory.

**Owner:** Documentation + Research + Maintenance. Correct current launch/import instructions and distinguish historical snapshots from current guarantees. Archive only explicitly identified obsolete reports with exact contents and repaired incoming links. Preserve notebooks, `.specstory`, scientific outputs, checkpoints, symlinks, and unknown files. The pre-existing dirty worktree is user work, not disposable clutter. Correct source invocation paths or clearly document their required import paths; do not execute long diagnostic experiments for cleanup.

### R9 — P2: baseline tests miss the release failure modes

**Evidence:** `test/run_tests.py` discovers only `test/{unit,regression,integration}`; integration has no substantive tests. Existing model-shape/util/frame checks do not exercise restart identity, path containment, model retention, or sparse-frame physics. Parent reported the baseline 10 tests passing and 13 additional crescent tests passing separately; these are not end-to-end deployment evidence.

**Owner:** Maintenance with each correction owner. Add targeted regressions for R1–R5/R7, run the existing suite, and verify the actual imported source before deployment. A subsequent representative Hub browser workflow is still needed; mock-based route tests cannot establish actual model/TDMS/browser compatibility.

### R10 — P3: resource bounds and module boundaries need a later pass

**Evidence:** `web/services/tdms_cache.py` limits cache entries to four rather than bytes and calls full image extraction under one global lock. TDMS MP4 export builds a complete normalized frame list, then may base64-encode the complete file. Training, batch detection, and rendering start daemon threads without a common per-user resource budget. `web/app.py` combines model training, detection, tracking, plotting, and file operations; the large inline SPA couples their presentation.

**Owner:** Web + Maintenance. Measure realistic stack memory and job concurrency before choosing byte budgets, streaming exports, or a worker queue. Incremental service extraction can follow stable tests. These are evidenced scaling limitations, not measured current out-of-memory failures; avoid an unrequested broad rewrite.
